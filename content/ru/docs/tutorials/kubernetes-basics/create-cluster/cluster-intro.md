## Кластеры Kubernetes

{{% alert %}}
_Kubernetes — платформа с открытым исходным кодом production-уровня, которая оркестрирует
размещение (планирование) контейнеров приложений и их запуск в рамках одного 
или нескольких компьютерных кластеров._
{{% /alert %}}

**Kubernetes координирует высокодоступный кластер компьютеров, которые работают
как единое целое.** Абстракции Kubernetes позволяют развёртывать контейнеризованные
приложения в кластере, не привязывая их к конкретным машинам. Чтобы использовать
такую модель развёртывания, приложения нужно упаковать так, чтобы они были отделены
от отдельных хостов: они должны быть контейнеризованы. Контейнеризованные приложения
более гибкие и доступные, чем в прежних моделях развёртывания, где приложения
устанавливались напрямую на конкретные машины как пакеты, глубоко интегрированные
с хостом. **Kubernetes автоматизирует распределение и планирование контейнеров
приложений по кластеру более эффективным способом.** Kubernetes — готовая к
production-использованию платформа с открытым исходным кодом.

Кластер Kubernetes состоит из двух типов ресурсов:

* **Управляющий слой** координирует работу кластера.
* **Узлы** — это рабочие машины, на которых запускаются приложения.

### Схема кластера

{{< figure src="/docs/tutorials/kubernetes-basics/public/images/module_01_cluster.svg" style="width: 100%;" >}}

**Управляющий слой отвечает за управление кластером.** Он координирует все
действия в кластере: планирование приложений, поддержание желаемого состояния,
масштабирование приложений и развёртывание новых обновлений.

{{% alert %}}
_Управляющие слои управляют кластером и узлами, на которых размещаются
запущенные приложения._
{{% /alert %}}

**Узел — это виртуальная машина или физический компьютер, который служит рабочей
машиной в кластере Kubernetes.** На каждом узле работает Kubelet — агент, который
управляет узлом и взаимодействует с управляющим слоем Kubernetes. На узле также
должны быть инструменты для запуска контейнеров, например
{{< glossary_tooltip text="containerd" term_id="containerd" >}} или
{{< glossary_tooltip term_id="cri-o" >}}. Распространённая и поддерживаемая модель
развёртывания предполагает запуск компонентов управляющего слоя Kubernetes на
выделенных узлах управляющего слоя.

Когда вы развёртываете приложения в Kubernetes, вы указываете управляющему слою
запустить контейнеры приложения. Управляющий слой планирует запуск контейнеров
на узлах кластера. **Компоненты уровня узла, например kubelet, взаимодействуют с
управляющим слоем через [Kubernetes API](/ru/docs/concepts/overview/kubernetes-api/)**,
который предоставляется управляющим слоем. Конечные пользователи также могут
использовать Kubernetes API напрямую для взаимодействия с кластером.

Кластер Kubernetes можно развернуть на физических или виртуальных машинах. Для
начала разработки с Kubernetes можно использовать Minikube. Minikube — упрощённая
реализация Kubernetes, которая создаёт виртуальную машину на локальной машине и
развёртывает простой кластер из одного узла. Minikube доступен для Linux, macOS и
Windows. CLI Minikube предоставляет базовые операции для начальной настройки и управления
кластером: start, stop, status и delete.

## Создание кластера minikube

Чтобы запустить кластер minikube:

```shell
minikube start
```

Чтобы проверить состояние кластера:

```shell
minikube status
```

Полное пошаговое руководство, включая развёртывание первого приложения и знакомство с панелью Kubernetes, см. в [Hello Minikube](/ru/docs/tutorials/hello-minikube/).
