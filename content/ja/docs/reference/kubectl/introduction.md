kubectlはKubernetes APIを使用してKubernetesクラスタと対話するためのコマンドラインツールです。
アプリケーションのデプロイ、リソースの調査、ワークロードの管理などに使用できます。

この文書はkubectlを使用してKubernetes上でアプリケーションを宣言的に管理することに焦点を当てていますが、kubectlの他の機能についても解説します。

## コマンドファミリー {#command-families}

ほとんどのkubectlコマンドは通常以下のいずれかのカテゴリに分類されます。

| タイプ | 用途 | 説明 |
|----------------------------------------|----------------------------|----------------------------------------------------|
| 宣言的リソース管理 | デプロイメントと運用（例：GitOps） | リソース設定を使用してKubernetesワークロードを宣言的に管理する |
| 命令型リソース管理 | 開発専用 | コマンドライン引数とフラグを使用してKubernetesワークロードを管理するコマンドを実行する |
| ワークロードの状態を表示 | デバッグ | ワークロードに関する情報を表示する |
| コンテナとのやり取り | デバッグ | 実行、アタッチ、コピー、ログ |
| クラスターの管理 | クラスターの運営 | ノードのドレインとcordon |

## 宣言的アプリケーションの管理 {#declarative-application-management}

リソース管理の好ましい方法はkubectl *Apply*コマンドで利用中のリソース設定という宣言ファイルを使うことです。
このコマンドは、ローカル（またはリモート）のファイル構造を読み込み宣言された意図を反映するようにクラスタの状態を変更します。

{{< alert color="success" title="Apply" >}}
ApplyはKubernetesでリソースを管理するために好ましい方法です。
{{< /alert >}}

## ワークロードの状態を出力 {#printing-state-about-workloads}

ユーザーはワークロードの状態を確認する必要があります。

- リソースの要約された状態と情報を出力
- リソースの全体の状態と情報を出力
- リソースの特定のフィールドを出力
- ラベルをマッチするリソースを要請

## ワークロードをデバッグ {#debugging-workloads}

kubectlは次のコマンドを提供してデバッグを支援します:

- コンテナのログを出力
- クラスターのイベントを出力
- コンテナにアタッチまたは実行
- クラスターのコンテナからユーザーのファイルシステムにファイルをコピー

## クラスターの管理 {#cluster-management}

たまに、ユーザーはクラスターのノードで作業をする必要があります。
kubectlはノードからワークロードをドレインするコマンドでノードを除外したりデバッグできるようにしてくれます。

## ポーセリン {#porcelain}

ユーザーはリソース設定お使用することが開発においては冗長すぎると感じ、シェルライクなワークフローでクラスターを命令型に操作することを好む場合があります。
kubectlはリソースの生成と変更のためのポーセリンコマンドを提供します。

- Deployment、StatefulSet、Service、ConfigMapなどのリソースの生成よ作成
- リソースのフィールドの設定
- テキストエディターを利用した（現在）リソースの編集

{{< alert color="warning" title="ポーせりんコマンドは開発専用" >}}
ポーセリンコマンドは開発クラスターでワークロードをテストする際に時間を節約できますが、本番環境では使用してはいけません。
{{< /alert >}}
