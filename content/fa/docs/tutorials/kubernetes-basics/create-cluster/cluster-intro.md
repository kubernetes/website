## {{% heading "objectives" %}}

* با مفهوم کلاستر کوبرنتیز آشنا شوید.
* با Minikube آشنا شوید.
* یک کلاستر کوبرنتیز را روی کامپیوتر خود راه‌اندازی کنید.

## {{% heading "prerequisites" %}}

این آموزش فرض می‌کند که `minikube` را از قبل نصب کرده‌اید.
برای دستورالعمل نصب، صفحه [minikube start](https://minikube.sigs.k8s.io/docs/start/) را ببینید.
{{< note >}}
فقط دستورالعمل‌های **مرحله ۱: نصب (Installation)** را اجرا کنید. بقیه مراحل در همین آموزش پوشش داده شده‌اند.
{{< /note >}}

همچنین باید `kubectl` را نصب کنید.
برای دستورالعمل نصب، صفحه [نصب ابزارها](/docs/tasks/tools/#kubectl) را ببینید.

دستورهای shell در این آموزش از نحو shell مطابق استاندارد POSIX استفاده می‌کنند که
shellهای پیش‌فرض بیشتر سیستم‌های لینوکس و macOS (برای مثال bash، zsh یا sh) از آن پشتیبانی می‌کنند.
کاربران ویندوز برای اجرای دستورها به همان شکلی که نوشته شده‌اند، باید از یک shell سازگار با POSIX مانند
[Windows Subsystem for Linux (WSL)](https://learn.microsoft.com/en-us/windows/wsl/install)
یا [Git Bash](https://gitforwindows.org/) استفاده کنند.
دستورهایی که از `export`، `$()` و ساختارهای مشابه استفاده می‌کنند، با
PowerShell یا Command Prompt ویندوز سازگار **نیستند**.

## کلاسترهای کوبرنتیز {#kubernetes-clusters}

{{% alert %}}
_کوبرنتیز یک پلتفرم متن‌باز و در سطح عملیاتی است که جای‌گذاری (زمان‌بندی) و اجرای
کانتینرهای برنامه را درون کلاسترهای کامپیوتری و در سراسر آن‌ها هماهنگ می‌کند._
{{% /alert %}}

**کوبرنتیز کلاستری با دسترس‌پذیری بالا را هماهنگ می‌کند که از کامپیوترهای متصل به هم
تشکیل شده و مانند یک واحد یکپارچه کار می‌کند.** انتزاع‌های کوبرنتیز به شما امکان می‌دهند
برنامه‌های کانتینری‌شده را روی کلاستر مستقر کنید، بدون اینکه آن‌ها را به ماشین‌های
مشخصی وابسته کنید. برای استفاده از این مدل جدید استقرار، برنامه‌ها باید طوری بسته‌بندی
شوند که از میزبان‌های مشخص جدا باشند؛ یعنی باید کانتینری شوند.
برنامه‌های کانتینری‌شده نسبت به مدل‌های استقرار گذشته انعطاف‌پذیرتر هستند و دسترس‌پذیری بیشتری دارند.
در آن مدل‌ها، برنامه‌ها به‌صورت بسته‌هایی که عمیقاً با میزبان یکپارچه بودند، مستقیماً روی
ماشین‌های مشخصی نصب می‌شدند. **کوبرنتیز توزیع و زمان‌بندی کانتینرهای برنامه را
در سراسر کلاستر به شکلی کارآمدتر خودکار می‌کند.** کوبرنتیز یک پلتفرم
متن‌باز و آماده برای محیط عملیاتی است.

یک کلاستر کوبرنتیز از دو نوع منبع تشکیل شده است:

* **Control Plane** کلاستر را هماهنگ می‌کند.
* **گره‌ها (Nodes)** ماشین‌های worker هستند که برنامه‌ها را اجرا می‌کنند.

### نمودار کلاستر {#cluster-diagram}

{{< figure src="/docs/tutorials/kubernetes-basics/public/images/module_01_cluster.svg" style="width: 100%;" >}}

**Control Plane مسئول مدیریت کلاستر است.** Control Plane همه فعالیت‌های
کلاستر شما را هماهنگ می‌کند؛ مانند زمان‌بندی برنامه‌ها، حفظ وضعیت مطلوب برنامه‌ها،
تغییر مقیاس برنامه‌ها و انتشار به‌روزرسانی‌های جدید.

{{% alert %}}
_Control Plane کلاستر و گره‌هایی را که میزبان برنامه‌های در حال اجرا هستند،
مدیریت می‌کند._
{{% /alert %}}

**گره یک ماشین مجازی (VM) یا یک کامپیوتر فیزیکی است که به‌عنوان ماشین worker در کلاستر
کوبرنتیز عمل می‌کند.** هر گره یک Kubelet دارد که عاملی برای مدیریت گره و
ارتباط با control plane کوبرنتیز است. گره همچنین باید ابزارهایی برای
انجام عملیات کانتینر داشته باشد، مانند {{< glossary_tooltip text="containerd" term_id="containerd" >}}
یا {{< glossary_tooltip term_id="cri-o" >}}. یک مدل استقرار رایج و پشتیبانی‌شده،
اجزای control plane کوبرنتیز را روی گره‌های control plane اختصاصی اجرا می‌کند.

وقتی برنامه‌ها را روی کوبرنتیز مستقر می‌کنید، به control plane می‌گویید کانتینرهای
برنامه را اجرا کند. سپس control plane کانتینرها را برای اجرا روی
گره‌های کلاستر زمان‌بندی می‌کند. **اجزای سطح گره، مانند kubelet، از طریق
[API کوبرنتیز](/docs/concepts/overview/kubernetes-api/) با control plane ارتباط برقرار می‌کنند**؛
این API را خود control plane در دسترس قرار می‌دهد. کاربران نهایی نیز می‌توانند مستقیماً از API کوبرنتیز
برای تعامل با کلاستر استفاده کنند.

یک کلاستر کوبرنتیز را می‌توان روی ماشین‌های فیزیکی یا مجازی مستقر کرد. برای
شروع توسعه با کوبرنتیز، می‌توانید از Minikube استفاده کنید. Minikube یک پیاده‌سازی سبک
از کوبرنتیز است که یک ماشین مجازی روی ماشین محلی شما ایجاد می‌کند و یک
کلاستر ساده با تنها یک گره مستقر می‌کند. Minikube برای سیستم‌های لینوکس، macOS
و ویندوز در دسترس است. رابط خط فرمان Minikube عملیات پایه راه‌اندازی را برای
کار با کلاستر فراهم می‌کند؛ از جمله start، stop، status و delete.

## ساخت یک کلاستر minikube {#create-a-minikube-cluster}

برای راه‌اندازی یک کلاستر minikube:

```shell
minikube start
```

برای بررسی وضعیت کلاستر:

```shell
minikube status
```

برای یک راهنمای کامل، از جمله استقرار اولین برنامه و بررسی داشبورد کوبرنتیز، آموزش [سلام Minikube](/docs/tutorials/hello-minikube/) را ببینید.
