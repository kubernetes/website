## {{% heading "objectives" %}}

* با پادهای کوبرنتیز آشنا شوید.
* با گره‌های کوبرنتیز آشنا شوید.
* مشکلات برنامه‌های مستقرشده را عیب‌یابی کنید.

## {{% heading "prerequisites" %}}

دستورهای shell در این آموزش از نحو shell مطابق استاندارد POSIX استفاده می‌کنند که
shellهای پیش‌فرض بیشتر سیستم‌های لینوکس و macOS (برای مثال bash، zsh یا sh) از آن پشتیبانی می‌کنند.
کاربران ویندوز برای اجرای دستورها به همان شکلی که نوشته شده‌اند، باید از یک shell سازگار با POSIX مانند
[Windows Subsystem for Linux (WSL)](https://learn.microsoft.com/en-us/windows/wsl/install)
یا [Git Bash](https://gitforwindows.org/) استفاده کنند.
دستورهایی که از `export`، `$()` و ساختارهای مشابه استفاده می‌کنند، با
PowerShell یا Command Prompt ویندوز سازگار **نیستند**.


## پادهای کوبرنتیز {#kubernetes-pods}

{{% alert %}}
_پاد گروهی از یک یا چند کانتینر برنامه (مانند Docker) است که فضای ذخیره‌سازی مشترک
(حجم‌ها)، آدرس IP و اطلاعاتی درباره نحوه اجرای آن‌ها را نیز در بر می‌گیرد._
{{% /alert %}}

وقتی در [ماژول ۲](/docs/tutorials/kubernetes-basics/deploy-app/deploy-intro/) یک Deployment ساختید،
کوبرنتیز یک **پاد** ایجاد کرد تا نمونه برنامه شما را میزبانی کند. پاد یک انتزاع کوبرنتیز است
که گروهی از یک یا چند کانتینر برنامه (مانند Docker) و برخی منابع مشترک برای آن کانتینرها را
نشان می‌دهد. این منابع عبارت‌اند از:

* فضای ذخیره‌سازی مشترک، به‌صورت حجم‌ها (Volumes)
* شبکه، به‌صورت یک آدرس IP یکتا در کلاستر
* اطلاعاتی درباره نحوه اجرای هر کانتینر، مانند نسخه image کانتینر
یا پورت‌های مشخصی که باید استفاده شوند

پاد یک «میزبان منطقی» مختص برنامه را مدل می‌کند و می‌تواند کانتینرهای برنامه متفاوتی را
در بر بگیرد که وابستگی نسبتاً تنگاتنگی به هم دارند. برای مثال، یک پاد ممکن است هم کانتینر
حاوی برنامه Node.js شما را داشته باشد و هم کانتینر دیگری را که داده‌های لازم برای انتشار را
به وب‌سرور Node.js می‌رساند. کانتینرهای یک پاد آدرس IP و فضای پورت یکسانی دارند،
همیشه کنار هم قرار می‌گیرند، با هم زمان‌بندی می‌شوند و در زمینه‌ای مشترک روی یک گره
اجرا می‌شوند.

پادها واحد اتمی پلتفرم کوبرنتیز هستند. وقتی روی کوبرنتیز یک Deployment می‌سازیم،
آن Deployment پادهایی ایجاد می‌کند که کانتینرها درون آن‌ها هستند (به‌جای اینکه مستقیماً
کانتینر بسازد). هر پاد به گره‌ای که روی آن زمان‌بندی شده، وابسته است و تا زمان خاتمه
(بر اساس سیاست راه‌اندازی مجدد) یا حذف، روی همان گره می‌ماند. اگر گره‌ای از کار بیفتد،
پادهای یکسانی روی دیگر گره‌های در دسترس کلاستر زمان‌بندی می‌شوند.

## گره‌ها {#nodes}

پاد همیشه روی یک **گره** اجرا می‌شود. گره یک ماشین worker در کوبرنتیز است و بسته به کلاستر،
می‌تواند یک ماشین مجازی یا فیزیکی باشد. هر گره را control plane مدیریت می‌کند. یک گره
می‌تواند چند پاد داشته باشد و control plane کوبرنتیز پادها را به‌طور خودکار روی گره‌های
کلاستر زمان‌بندی می‌کند. زمان‌بندی خودکار control plane منابع در دسترس هر گره را
در نظر می‌گیرد.

هر گره کوبرنتیز دست‌کم این موارد را اجرا می‌کند:

* Kubelet، فرایندی که مسئول ارتباط بین control plane کوبرنتیز و گره است؛ این فرایند
پادها و کانتینرهای در حال اجرا روی یک ماشین را مدیریت می‌کند.

* یک محیط اجرای کانتینر (container runtime)، مانند containerd، که مسئول دریافت image کانتینر
از یک رجیستری، باز کردن بسته‌بندی کانتینر و اجرای برنامه است.

## عیب‌یابی با kubectl {#troubleshooting-with-kubectl}

در [ماژول ۲](/docs/tutorials/kubernetes-basics/deploy-app/deploy-intro/)، از رابط خط فرمان
kubectl استفاده کردید. در ماژول ۳ همچنان از آن برای گرفتن اطلاعات درباره برنامه‌های مستقرشده و
محیط‌های آن‌ها استفاده می‌کنید. رایج‌ترین عملیات را می‌توان با زیردستورهای kubectl
زیر انجام داد:

* `kubectl get` - فهرست کردن منابع
* `kubectl describe` - نمایش اطلاعات مفصل درباره یک منبع
* `kubectl logs` - چاپ لاگ‌های یک کانتینر در یک پاد
* `kubectl exec` - اجرای یک دستور روی یک کانتینر در یک پاد

با این دستورها می‌توانید ببینید برنامه‌ها چه زمانی مستقر شده‌اند، وضعیت فعلی آن‌ها چیست،
کجا اجرا می‌شوند و چه پیکربندی‌ای دارند.

حالا که درباره اجزای کلاستر و خط فرمان بیشتر می‌دانیم، بیایید در برنامه خود کاوش کنیم.

### بررسی پیکربندی برنامه {#check-application-configuration}

بیایید مطمئن شویم برنامه‌ای که در سناریوی قبلی مستقر کردیم، در حال اجراست.
از دستور `kubectl get` استفاده می‌کنیم و دنبال پادهای موجود می‌گردیم:

```shell
kubectl get pods
```

اگر هیچ پادی در حال اجرا نیست، چند ثانیه صبر کنید و دوباره پادها را فهرست کنید.
وقتی دیدید یک پاد در حال اجراست، می‌توانید ادامه دهید.

سپس، برای دیدن اینکه چه کانتینرهایی درون آن پاد هستند و از چه imageهایی برای ساختن
آن کانتینرها استفاده شده است، دستور `kubectl describe pods` را اجرا می‌کنیم:

```shell
kubectl describe pods
```

اینجا جزئیات کانتینر پاد را می‌بینیم: آدرس IP، پورت‌های استفاده‌شده و فهرستی از
رویدادهای مربوط به چرخه عمر پاد.

خروجی زیردستور `describe` مفصل است و مفاهیمی را در بر می‌گیرد که هنوز توضیح نداده‌ایم،
اما نگران نباشید؛ تا پایان این آموزش با آن‌ها آشنا می‌شوید.

{{< alert color="info" title="توجه" >}}
با زیردستور `describe` می‌توانید اطلاعات مفصلی درباره بیشتر اجزای پایه کوبرنتیز، از جمله
گره‌ها، پادها و Deploymentها، به دست آورید. خروجی describe برای خواندن انسان
طراحی شده است، نه برای پردازش با اسکریپت.
{{< /alert >}}

### نمایش برنامه در ترمینال {#show-the-app-in-the-terminal}

به یاد بیاورید که پادها روی یک شبکه خصوصی و ایزوله اجرا می‌شوند؛ پس برای اشکال‌زدایی و
تعامل با آن‌ها، باید دسترسی را از طریق پروکسی برقرار کنیم. برای این کار، از دستور
`kubectl proxy` استفاده می‌کنیم تا یک پروکسی را در یک **ترمینال دوم** اجرا کنیم.
یک پنجره ترمینال جدید باز کنید و این دستور را در آن اجرا کنید:

```shell
kubectl proxy
```

حالا دوباره نام پاد را می‌گیریم و از طریق پروکسی، مستقیماً از آن پاد پرس‌وجو می‌کنیم.
برای گرفتن نام پاد و ذخیره آن در متغیر محیطی `POD_NAME`:

```shell
export POD_NAME="$(kubectl get pods -o go-template --template '{{range .items}}{{.metadata.name}}{{"\n"}}{{end}}')"
echo Name of the Pod: $POD_NAME
```

برای دیدن خروجی برنامه، یک درخواست `curl` اجرا کنید:

```shell
curl http://localhost:8001/api/v1/namespaces/default/pods/$POD_NAME:8080/proxy/
```

این URL مسیر رسیدن به API پاد است.

{{< alert color="info" title="توجه" >}}
لازم نیست نام کانتینر را مشخص کنیم، چون فقط یک کانتینر درون پاد داریم.
{{< /alert >}}

### اجرای دستورها روی کانتینر {#executing-commands-on-the-container}

وقتی پاد راه‌اندازی شده و در حال اجرا باشد، می‌توانیم دستورها را مستقیماً روی کانتینر اجرا کنیم.
برای این کار، از زیردستور `exec` استفاده می‌کنیم و نام پاد را به‌عنوان پارامتر به آن می‌دهیم.
بیایید متغیرهای محیطی را فهرست کنیم:

```shell
kubectl exec "$POD_NAME" -- env
```

باز هم یادآوری می‌کنیم که چون فقط یک کانتینر در پاد داریم، نیازی به نوشتن نام خود
کانتینر نیست.

سپس بیایید یک نشست bash در کانتینر پاد شروع کنیم:

```shell
kubectl exec -ti $POD_NAME -- bash
```

اکنون یک کنسول باز روی کانتینری داریم که برنامه NodeJS ما در آن اجرا می‌شود.
کد منبع برنامه در فایل `server.js` است:

```shell
cat server.js
```

می‌توانید با اجرای یک دستور curl بررسی کنید که برنامه در حال اجرا باشد:

```shell
curl http://localhost:8080
```

{{< alert color="info" title="توجه" >}}
اینجا از `localhost` استفاده کردیم، چون دستور را درون پاد NodeJS اجرا کردیم.
اگر نمی‌توانید به `localhost:8080` وصل شوید، مطمئن شوید که `kubectl exec` را
اجرا کرده‌اید و دستور را از درون پاد اجرا می‌کنید.
{{< /alert >}}

برای بستن اتصال به کانتینر، `exit` را تایپ کنید.
