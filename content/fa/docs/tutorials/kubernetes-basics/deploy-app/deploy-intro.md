## {{% heading "objectives" %}}

* با Deployment برنامه‌ها آشنا شوید.
* اولین برنامه خود را با kubectl روی کوبرنتیز مستقر کنید.


## {{% heading "prerequisites" %}}

دستورهای shell در این آموزش از نحو shell مطابق استاندارد POSIX استفاده می‌کنند که
shellهای پیش‌فرض بیشتر سیستم‌های لینوکس و macOS (برای مثال bash، zsh یا sh) از آن پشتیبانی می‌کنند.
کاربران ویندوز برای اجرای دستورها به همان شکلی که نوشته شده‌اند، باید از یک shell سازگار با POSIX مانند
[Windows Subsystem for Linux (WSL)](https://learn.microsoft.com/en-us/windows/wsl/install)
یا [Git Bash](https://gitforwindows.org/) استفاده کنند.
دستورهایی که از `export`، `$()` و ساختارهای مشابه استفاده می‌کنند، با
PowerShell یا Command Prompt ویندوز سازگار **نیستند**.


## Deploymentهای کوبرنتیز {#kubernetes-deployments}

{{% alert %}}
_Deployment مسئول ساخت و به‌روزرسانی نمونه‌های برنامه شما است._
{{% /alert %}}

{{< alert color="info" title="توجه" >}}
این آموزش از کانتینری استفاده می‌کند که به معماری AMD64 نیاز دارد. اگر از
minikube روی کامپیوتری با معماری CPU متفاوت استفاده می‌کنید، می‌توانید minikube را با
درایوری امتحان کنید که بتواند AMD64 را شبیه‌سازی کند. برای مثال، درایور Docker Desktop این کار را انجام می‌دهد.
{{< /alert >}}

وقتی یک [کلاستر کوبرنتیز در حال اجرا](/docs/tutorials/kubernetes-basics/create-cluster/cluster-intro/) داشته باشید،
می‌توانید برنامه‌های کانتینری‌شده خود را روی آن مستقر کنید. برای این کار، یک
**Deployment** کوبرنتیز می‌سازید. Deployment به کوبرنتیز می‌گوید نمونه‌های برنامه شما را
چگونه بسازد و به‌روزرسانی کند. پس از ساختن Deployment، control plane کوبرنتیز
نمونه‌های برنامه‌ای را که در آن Deployment تعریف شده‌اند، برای اجرا روی گره‌های مختلف
کلاستر زمان‌بندی می‌کند.

پس از ساخته شدن نمونه‌های برنامه، یک کنترل‌کننده Deployment کوبرنتیز به‌طور پیوسته
این نمونه‌ها را پایش می‌کند. اگر گره‌ای که میزبان یک نمونه است از کار بیفتد یا حذف شود،
کنترل‌کننده Deployment آن نمونه را با نمونه‌ای روی گره دیگری از کلاستر جایگزین می‌کند.
**این کار یک سازوکار خودترمیمی برای مقابله با خرابی یا نگهداری ماشین فراهم می‌کند.**

در دوران پیش از هماهنگ‌سازی (orchestration)، معمولاً از اسکریپت‌های نصب برای راه‌اندازی
برنامه‌ها استفاده می‌شد، اما این اسکریپت‌ها امکان بازیابی پس از خرابی ماشین را فراهم نمی‌کردند.
Deploymentهای کوبرنتیز با ساختن نمونه‌های برنامه و اجرا نگه داشتن آن‌ها در سراسر گره‌ها،
رویکردی اساساً متفاوت برای مدیریت برنامه‌ها ارائه می‌دهند.

## استقرار اولین برنامه روی کوبرنتیز {#deploying-your-first-app-on-kubernetes}

{{% alert %}}
_برای استقرار برنامه‌ها روی کوبرنتیز، باید آن‌ها را در یکی از قالب‌های کانتینر
پشتیبانی‌شده بسته‌بندی کنید._
{{% /alert %}}

{{< figure src="/docs/tutorials/kubernetes-basics/public/images/module_02_first_app.svg" class="diagram-medium" >}}

می‌توانید با رابط خط فرمان کوبرنتیز، [kubectl](/docs/reference/kubectl/)، یک Deployment
بسازید و آن را مدیریت کنید. `kubectl` برای تعامل با کلاستر از API کوبرنتیز استفاده می‌کند.
در این ماژول، رایج‌ترین دستورهای `kubectl` را یاد می‌گیرید که برای ساختن Deploymentهایی
لازم‌اند که برنامه‌های شما را روی یک کلاستر کوبرنتیز اجرا می‌کنند.

وقتی یک Deployment می‌سازید، باید image کانتینر برنامه و تعداد رپلیکاهایی را که
می‌خواهید اجرا شوند، مشخص کنید. بعداً می‌توانید با به‌روزرسانی Deployment این اطلاعات را
تغییر دهید. [ماژول ۵](/docs/tutorials/kubernetes-basics/scale/scale-intro/)
و [ماژول ۶](/docs/tutorials/kubernetes-basics/update/update-intro/) این دوره آموزشی
توضیح می‌دهند که چگونه مقیاس Deploymentهای خود را تغییر دهید و آن‌ها را به‌روزرسانی کنید.

برای اولین Deployment خود، از یک برنامه hello-node استفاده می‌کنید که در یک کانتینر Docker
بسته‌بندی شده است و با استفاده از NGINX همه درخواست‌ها را عیناً برمی‌گرداند. (اگر هنوز
ساختن یک برنامه hello-node و استقرار آن با یک کانتینر را امتحان نکرده‌اید، می‌توانید ابتدا
دستورالعمل‌های آموزش [سلام Minikube](/docs/tutorials/hello-minikube/) را دنبال کنید.)

همچنین باید kubectl را نصب کرده باشید. اگر لازم است آن را نصب کنید، صفحه
[نصب ابزارها](/docs/tasks/tools/#kubectl) را ببینید.

حالا که می‌دانید Deployment چیست، بیایید اولین برنامه خود را مستقر کنیم!

### مبانی kubectl {#kubectl-basics}

قالب رایج یک دستور kubectl به این شکل است: `kubectl action resource`.

این دستور _عمل_ مشخص‌شده (مانند `create`، `describe` یا `delete`) را روی
_منبع_ مشخص‌شده (مانند `node` یا `deployment`) انجام می‌دهد. می‌توانید بعد از
زیردستور از `--help` استفاده کنید تا اطلاعات بیشتری درباره پارامترهای ممکن بگیرید
(برای مثال: `kubectl get nodes --help`).

با اجرای دستور `kubectl version` بررسی کنید که kubectl برای ارتباط با کلاستر شما پیکربندی شده باشد.

بررسی کنید که kubectl نصب شده باشد و بتوانید نسخه‌های کلاینت و سرور را ببینید.

برای دیدن گره‌های کلاستر، دستور `kubectl get nodes` را اجرا کنید.

گره‌های در دسترس را می‌بینید. بعداً کوبرنتیز بر اساس منابع در دسترس گره‌ها انتخاب می‌کند
که برنامه ما را کجا مستقر کند.

### استقرار یک برنامه {#deploy-an-app}

بیایید اولین برنامه خود را با دستور `kubectl create deployment` روی کوبرنتیز مستقر کنیم.
باید نام Deployment و محل image برنامه را مشخص کنیم (برای imageهایی که بیرون از Docker Hub
میزبانی می‌شوند، URL کامل مخزن را وارد کنید).

```shell
kubectl create deployment kubernetes-bootcamp --image=gcr.io/google-samples/kubernetes-bootcamp:v1
```

عالی است! با ساختن یک Deployment، اولین برنامه خود را مستقر کردید. این کار چند مرحله را برای شما انجام داد:

* یک گره مناسب برای اجرای نمونه‌ای از برنامه پیدا کرد (ما فقط ۱ گره در دسترس داریم)
* برنامه را برای اجرا روی آن گره زمان‌بندی کرد
* کلاستر را طوری پیکربندی کرد که در صورت نیاز، نمونه را روی یک گره جدید دوباره زمان‌بندی کند

برای فهرست کردن Deploymentهای خود، از دستور `kubectl get deployments` استفاده کنید:

```shell
kubectl get deployments
```

می‌بینیم که ۱ Deployment وجود دارد که یک نمونه از برنامه شما را اجرا می‌کند. این نمونه
درون یک کانتینر روی گره شما اجرا می‌شود.

### مشاهده برنامه {#view-the-app}

[پادهایی](/docs/concepts/workloads/pods/) که درون کوبرنتیز اجرا می‌شوند، روی یک شبکه
خصوصی و ایزوله اجرا می‌شوند. به‌طور پیش‌فرض، این پادها از پادها و سرویس‌های دیگر در
همان کلاستر کوبرنتیز دیده می‌شوند، اما از بیرون آن شبکه دیده نمی‌شوند. وقتی از `kubectl`
استفاده می‌کنیم، از طریق یک نقطه پایانی (endpoint) در API با برنامه خود ارتباط برقرار می‌کنیم.

گزینه‌های دیگر برای در دسترس قرار دادن برنامه بیرون از کلاستر کوبرنتیز را بعداً در
[ماژول ۴](/docs/tutorials/kubernetes-basics/expose/) پوشش می‌دهیم.
همچنین، چون این یک آموزش پایه است، اینجا به‌طور مفصل توضیح نمی‌دهیم که پادها چه هستند؛
این موضوع در بخش‌های بعدی پوشش داده می‌شود.

دستور `kubectl proxy` می‌تواند یک پروکسی بسازد که ارتباطات را به شبکه خصوصی
سراسری کلاستر هدایت می‌کند. پروکسی را می‌توان با فشردن control-C متوقف کرد و تا زمانی که
در حال اجراست، هیچ خروجی‌ای نشان نمی‌دهد.

**برای اجرای پروکسی باید یک پنجره ترمینال دوم باز کنید.**

```shell
kubectl proxy
```
اکنون بین میزبان ما (ترمینال) و کلاستر کوبرنتیز یک اتصال برقرار است.
پروکسی دسترسی مستقیم به API را از این ترمینال‌ها ممکن می‌کند.

می‌توانید همه APIهایی را که از طریق نقطه پایانی (endpoint) پروکسی میزبانی می‌شوند، ببینید. برای مثال،
می‌توانیم با دستور `curl` نسخه را مستقیماً از طریق API پرس‌وجو کنیم:

```shell
curl http://localhost:8001/version
```

{{< alert color="info" title="توجه" >}}
اگر پورت 8001 در دسترس نیست، مطمئن شوید که `kubectl proxy` که بالاتر اجرا کردید،
هنوز در ترمینال دوم در حال اجراست.
{{< /alert >}}

سرور API به‌طور خودکار برای هر پاد، بر اساس نام آن، یک نقطه پایانی (endpoint) می‌سازد که از طریق
پروکسی هم در دسترس است.

ابتدا باید نام پاد را بگیریم و آن را در متغیر محیطی `POD_NAME` ذخیره کنیم.

```shell
export POD_NAME=$(kubectl get pods -o go-template --template '{{range .items}}{{.metadata.name}}{{"\n"}}{{end}}')
echo Name of the Pod: $POD_NAME
```

با اجرای دستور زیر، می‌توانید از طریق API پروکسی‌شده به پاد دسترسی داشته باشید:

```shell
curl http://localhost:8001/api/v1/namespaces/default/pods/$POD_NAME:8080/proxy/
```

برای اینکه Deployment جدید بدون استفاده از پروکسی در دسترس باشد، به یک Service نیاز است
که در [ماژول ۴](/docs/tutorials/kubernetes-basics/expose/) توضیح داده می‌شود.
