kubectl은 Kubernetes API를 사용하여 Kubernetes 클러스터와 상호 작용하는 명령줄 도구이다.
이를 통해 애플리케이션를 배포하고, 리소스를 검사하며, 워크로드를 관리할 수 있다.

이 글에서는 주로 kubectl을 사용하여 Kubernetes에서 애플리케이션을 선언적으로 관리하는 방법을 소개한다.
또한 kubectl의 다른 기능들도 다룬다.

## 명령어 분류

대부분의 kubectl 명령어는 일반적으로 다음과 같이 분류할 수 있다.

| 유형                                   | 용도                       | 설명                                         |
|----------------------------------------|----------------------------|----------------------------------------------------|
| 선언적 리소스 관리  | 배포 및 운영(예: GitOps) | 리소스 관리를 활용한 Kubernetes 워크로드의 선언적 관리 |
| 명령 자원 관리  | 개발 전용 | 명령줄 인수와 플래그를 사용하여 Kubernetes 워크로드를 관리한다. |
| 워크로드 상태 출력  | 디버그  | 워크로드에 관한 정보를 출력한다. |
| 컨테이너와의 상호작용 | 디버그 | 실행, 어태치, 복사, 로그출력 | 
| 클러스터 관리 | 클러스터 운영 | 드레인과 노드 차단 |

## 선언적 애플리케이션 관리

리소스를 관리하는 가장 좋은 방법은 resource라고 하는
선언적 파일과 함께 kubectl *Apply* 명령을 사용하는 것이다.
이 명령은 로컬(또는 원격) 파일 구조를 읽고 선언 의도를 반영하도록 클러스터 
상태를 수정한다.

{{< alert color="success" title="Apply" >}}
Apply 는 쿠버네티스 클러스터에서 리소스를 관리하는 선호되는 방법이다.
{{< /alert >}}

## 워크로드 상태 출력

사용자는 워크로드의 상태를 확인해야 할 때가 있다.

- 리소스의 상태요약과 정보를 출력
- 리소스의 완료상태와 정보를 출력
- 리소스의 특정 필드를 출력
- 라벨에 매칭하는 리소스를 요청

## 워크로드 디버깅

kubectl은 다음 명령어로 디버깅을 돕는다:

- 컨테이너 로그를 출력
- 클러스터 이벤트를 출력
- 컨테이너에 어태치하거나 실행
- 클러스터에 있는 컨테이터에서 사용자의 파일시스템으로 화일을 복사

## 클러스터 관리

사용자는 가끔 클러스터의 노드에서 작업을 해야 하는 경우가 있다.
kubectl은 노드에서 워크로드를 드레인하는 명령어를 지원하여 노드를 중지하거나 디버깅할 수 있게 해 준다.

## 포클레인 명령어

사용자는 *개발*과정에서 리소스구성을 사용하는 것이 번거롭다고 느껴서, 셸과 유사한 워크플로를 통해
클러스터에서 *명령형*으로 작업하는 것을 선호할 수 있다. kubectl은 리소스를 생성하고 수정하는 포클레인
명령어를 제공한다.

- 디플로이먼트(Deployment), 스테이트풀셋(StatefulSet), 서비스, 컨피그맵(ConfigMap)과 같은 리소스를 생성
- 리소스의 필드를 설정
- 편집기를 사용해서 리소스를 (실시간으로) 편집

{{< alert color="warning" title="개발 용도로만 포클레인 명령 사용하기" >}}
포클레인 명령은 개발클러스터의 워크로드를 실험하는 데 시간을 절약하게 해 주지만,
프로덕션 환경에서는 사용하면 안 됩니다.
{{< /alert >}}
