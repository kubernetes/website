kubectl은 쿠버네티스 API를 사용하여 쿠버네티스 클러스터와 상호 작용하는 명령줄 도구이다.
이를 통해 애플리케이션을 배포하고, 리소스를 검사하며, 워크로드를 관리할 수 있다.

이 글은 주로 kubectl을 사용하여 쿠버네티스에서 애플리케이션을 선언적으로 관리하는 방법을 다루지만,
kubectl의 다른 기능도 다룬다.

## 명령어 분류

대부분의 kubectl 명령어는 일반적으로 다음과 같이 분류할 수 있다.

| 유형                                   | 용도                       | 설명                                         |
|----------------------------------------|----------------------------|----------------------------------------------------|
| 선언적 리소스 관리 | 배포 및 운영(예: GitOps) | 리소스 구성(resource configuration)을 사용하여 쿠버네티스 워크로드를 선언적으로 관리 |
| 명령형 리소스 관리 | 개발 전용 | 명령줄 인수와 플래그로 명령을 실행하여 쿠버네티스 워크로드를 관리 |
| 워크로드 상태 출력 | 디버깅 | 워크로드에 관한 정보 출력 |
| 컨테이너와 상호 작용 | 디버깅 | exec, attach, cp, logs |
| 클러스터 관리 | 클러스터 운영 | 노드 드레인(drain) 및 스케줄 불가 설정(cordon) |

## 선언적 애플리케이션 관리

리소스를 관리하는 가장 좋은 방법은 리소스 구성이라고 하는
선언적 파일과 함께 kubectl *Apply* 명령을 사용하는 것이다.
이 명령은 로컬(또는 원격) 파일 구조를 읽고, 선언된 의도를 반영하도록
클러스터 상태를 수정한다.

{{< alert color="success" title="Apply" >}}
Apply는 쿠버네티스 클러스터에서 리소스를 관리하는 데 선호되는 방법이다.
{{< /alert >}}

## 워크로드 상태 출력

사용자는 워크로드의 상태를 확인해야 할 때가 있다.

- 리소스의 요약된 상태와 정보를 출력
- 리소스의 전체 상태와 정보를 출력
- 리소스의 특정 필드를 출력
- 레이블과 일치하는 리소스를 조회

## 워크로드 디버깅

kubectl은 다음 작업을 위한 명령어를 제공하여 디버깅을 지원한다.

- 컨테이너 로그를 출력
- 클러스터 이벤트를 출력
- 컨테이너에서 명령 실행(exec) 또는 컨테이너에 어태치(attach)
- 클러스터에 있는 컨테이너에서 사용자의 파일시스템으로 파일을 복사

## 클러스터 관리

사용자는 가끔 클러스터의 노드에서 작업을 해야 하는 경우가 있다.
kubectl은 노드에서 워크로드를 드레인하는 명령어를 지원하여, 노드를 운영에서 제외(decommission)하거나 디버깅할 수 있게 해 준다.

## 포슬린(porcelain) 명령어

사용자는 *개발* 과정에서 리소스 구성을 사용하는 것이 번거롭다고 느껴서, 셸과 유사한 워크플로를 통해
클러스터에서 *명령형*으로 작업하는 것을 선호할 수 있다. kubectl은 리소스를 생성하고 수정하는 포슬린
명령어를 제공한다.

- 디플로이먼트(Deployment), 스테이트풀셋(StatefulSet), 서비스, 컨피그맵(ConfigMap)과 같은 리소스를 생성
- 리소스의 필드를 설정
- 텍스트 편집기에서 리소스를 (실시간으로) 편집

{{< alert color="warning" title="포슬린 명령어는 개발 용도로만 사용" >}}
포슬린 명령어는 개발 클러스터에서 워크로드를 실험할 때 시간을 절약해 주지만,
프로덕션 환경에서는 사용하면 안 된다.
{{< /alert >}}
