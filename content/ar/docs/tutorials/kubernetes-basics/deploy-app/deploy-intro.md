## {{% heading "objectives" %}}

* تعلَّم عن نُشرات التطبيقات (Deployment).
* انشر تطبيقك الأول على كوبيرنيتيس باستخدام kubectl.

## {{% heading "prerequisites" %}}

وتستخدم أوامر shell في هذا الدليل صياغة POSIX، وهي مدعومة في الأصداف
الافتراضية في معظم أنظمة Linux وmacOS (مثل bash أو zsh أو sh). وعلى المستخدمين
في Windows استخدام shell متوافق مع POSIX مثل
[Windows Subsystem for Linux (WSL)](https://learn.microsoft.com/en-us/windows/wsl/install)
أو [Git Bash](https://gitforwindows.org/) لتشغيل الأوامر كما هي مكتوبة. أما
الأوامر التي تستخدم `export` و`$()` وما شابهها ف**غير** متوافقة مع PowerShell
أو موجه أوامر Windows.

## نُشرات كوبيرنيتيس {#kubernetes-deployments}

{{% alert %}}
_النشر هو المسؤول عن إنشاء نسخ من تطبيقك وتحديثها._
{{% /alert %}}

{{< alert color="info" title="ملاحظة" >}}
يستخدم هذا الدليل حاوية تتطلب معمارية AMD64. فإذا كنت تستخدم مينيكيوب على حاسوب
بمعمارية معالج مختلفة، فيمكنك تجربة مينيكيوب مع سائق قادر على محاكاة AMD64.
على سبيل المثال، يستطيع سائق Docker Desktop فعل ذلك.
{{< /alert >}}

وبعد أن يصبح لديك [عنقود كوبيرنيتيس قيد التشغيل](/ar/docs/tutorials/kubernetes-basics/create-cluster/cluster-intro/)،
يمكنك نشر تطبيقاتك المحتواة في حاويات فوقه. وللقيام بذلك، تنشئ **نشراً** في
كوبيرنيتيس. ويخبر النشر كوبيرنيتيس كيف ينشئ نسخ تطبيقك ويحدّثها. وبعد أن
تنشئ نشراً، يجدول مستوى تحكم كوبيرنيتيس نسخ التطبيق المشمولة بذلك النشر لتعمل
على العُقد المختلفة في العنقود.

وبعد إنشاء نسخ التطبيق، يراقب مُتحكّم النشر في كوبيرنيتيس هذه النسخ باستمرار.
فإذا تعطّلت العقدة التي تستضيف إحدى النسخ أو حُذفت، استبدل مُتحكّم النشر تلك
النسخة بنسخة أخرى على عقدة مختلفة في العنقود. **وهذا يوفّر آلية تعافٍ ذاتي
للتعامل مع أعطال الأجهزة أو أعمال الصيانة.**

وفي عالم ما قبل التنسيق، كانت سكربتات التثبيت تُستخدم غالباً لتشغيل التطبيقات،
لكنها لم تكن تسمح بالتعافي من أعطال الأجهزة. وبإنشاء نسخ تطبيقك والمحافظة على
تشغيلها عبر العُقد المختلفة، توفّر نُشرات كوبيرنيتيس منهجاً مختلفاً جوهرياً
لإدارة التطبيقات.

## نشر تطبيقك الأول على كوبيرنيتيس {#deploying-your-first-app-on-kubernetes}

{{% alert %}}
_يجب تعبئة التطبيقات في إحدى صيغ الحاويات المدعومة كي يمكن نشرها على
كوبيرنيتيس._
{{% /alert %}}

{{< figure src="/docs/tutorials/kubernetes-basics/public/images/module_02_first_app.svg" class="diagram-medium" >}}

ويمكنك إنشاء النشر وإدارته باستخدام واجهة سطر الأوامر في كوبيرنيتيس،
[kubectl](/docs/reference/kubectl/). ويستخدم `kubectl` واجهة برمجة تطبيقات
كوبيرنيتيس للتعامل مع العنقود. وفي هذه الوحدة، ستتعلّم أوامر `kubectl` الأكثر
شيوعاً اللازمة لإنشاء نُشرات تشغّل تطبيقاتك على عنقود كوبيرنيتيس.

وعند إنشاء نشر، ستحتاج إلى تحديد صورة الحاوية لتطبيقك وعدد النسخ التي تريد
تشغيلها. ويمكنك تغيير هذه المعلومات لاحقاً بتحديث النشر؛ وتشرح
[الوحدة 5](/docs/tutorials/kubernetes-basics/scale/scale-intro/)
و[الوحدة 6](/docs/tutorials/kubernetes-basics/update/update-intro/) من معسكر
التدريب كيف يمكنك توسيع نُشراتك وتحديثها.

ولأول نشر لك، ستستخدم تطبيق hello-node معبّأً في حاوية Docker تستخدم NGINX
لردّ جميع الطلبات. (وإذا لم تكن قد جرّبت من قبل إنشاء تطبيق hello-node
ونشره باستخدام حاوية، فيمكنك البدء بذلك باتباع تعليمات
[دليل Hello Minikube](/ar/docs/tutorials/hello-minikube/).)

كما ستحتاج إلى تثبيت kubectl. وإذا احتجت إلى تثبيته، فراجع
[تثبيت الأدوات](/docs/tasks/tools/#kubectl).

والآن بعد أن عرفت ما هي النُشرات، فلننشر تطبيقنا الأول!

### أساسيات kubectl {#kubectl-basics}

الصيغة الشائعة لأمر kubectl هي: `kubectl action resource`.

وهذا ينفّذ _الإجراء_ المحدد (مثل `create` أو `describe` أو `delete`) على
_المورد_ المحدد (مثل `node` أو `deployment`). ويمكنك استخدام `--help` بعد
الأمر الفرعي للحصول على معلومات إضافية عن المعاملات الممكنة (على سبيل المثال:
`kubectl get nodes --help`).

تحقّق من أن kubectl مُهيّأ للتحدث مع عنقودك، وذلك بتشغيل الأمر
`kubectl version`.

تحقّق من أن kubectl مثبّت وأنك ترى إصدارات العميل والخادم معاً.

ولعرض العُقد في العنقود، نفّذ الأمر `kubectl get nodes`.

وسترى العُقد المتاحة. وفي وقت لاحق، سيختار كوبيرنيتيس أين ينشر تطبيقنا بناءً على
الموارد المتاحة في العقد.

### نشر تطبيق {#deploy-an-app}

لننشر تطبيقنا الأول على كوبيرنيتيس باستخدام الأمر `kubectl create deployment`.
نحتاج إلى تحديد اسم النشر وموقع صورة التطبيق (أدرج عنوان المستودع كاملاً
للصور المستضافة خارج Docker Hub).

```shell
kubectl create deployment kubernetes-bootcamp --image=gcr.io/google-samples/kubernetes-bootcamp:v1
```

رائع! لقد نشرت تطبيقك الأول للتو بإنشاء نشر. وقد أنجز ذلك عدة أمور:

* البحث عن عقدة مناسبة يمكن تشغيل نسخة من التطبيق عليها (لدينا عقدة واحدة متاحة)
* جدولة التطبيق ليعمل على تلك العقدة
* تهيئة العنقود لإعادة جدولة النسخة على عقدة جديدة عند الحاجة

ولعرض نُشراتك، استخدم الأمر `kubectl get deployments`:

```shell
kubectl get deployments
```

ونرى أن هناك نشراً واحداً يشغّل نسخة واحدة من تطبيقك. وتعمل هذه النسخة داخل
حاوية على عقدتك.

### عرض التطبيق {#view-the-app}

الحجيرات ([Pods](/docs/concepts/workloads/pods/)) التي تعمل داخل كوبيرنيتيس تعمل
على شبكة خاصة معزولة. وبشكل افتراضي تكون مرئية من الحجيرات والخدمات الأخرى
داخل عنقود كوبيرنيتيس نفسه، لكنها غير مرئية من خارج تلك الشبكة. وعندما نستخدم
`kubectl` فإننا نتواصل عبر نقطة نهاية API للتواصل مع تطبيقك.

وسنغطي لاحقاً خيارات أخرى لإبراز تطبيقك خارج عنقود كوبيرنيتيس، في
[الوحدة 4](/docs/tutorials/kubernetes-basics/expose/).
ولأن هذا دليل تمهيدي، فلن نشرح هنا ما هي `Pods` بالتفصيل، بل ستُغطّى في
المواضيع اللاحقة.

ويمكن لأمر `kubectl proxy` إنشاء وكيل يوجّه الاتصالات إلى شبكة العنقود الخاصة
على مستوى العنقود كله. ويمكن إنهاء الوكيل بالضغط على control-C، ولن يعرض أي
مخرجات أثناء تشغيله.

**تحتاج إلى فتح نافذة طرفية ثانية لتشغيل الوكيل.**

```shell
kubectl proxy
```

أصبح لدينا الآن اتصال بين مضيفنا (الطرفية) وعنقود كوبيرنيتيس. ويتيح الوكيل
وصولاً مباشراً إلى API من هذه الطرفيات.

ويمكنك رؤية جميع واجهات API المتاحة عبر نقطة نهاية الوكيل. على سبيل المثال،
يمكنك الاستعلام عن الإصدار مباشرةً عبر API باستخدام أمر `curl`:

```shell
curl http://localhost:8001/version
```

{{< alert color="info" title="ملاحظة" >}}
إذا تعذّر الوصول إلى المنفذ 8001، فتأكد من أن `kubectl proxy` الذي شغّلته أعلاه
ما زال يعمل في الطرفية الثانية.
{{< /alert >}}

وسيقوم خادم API تلقائياً بإنشاء نقطة نهاية لكل حجيرة، مبنية على اسم الحجيرة،
وهي متاحة أيضاً عبر الوكيل.

نحتاج أولاً إلى الحصول على اسم الحجيرة، وسنخزّنه في متغيّر البيئة `POD_NAME`.

```shell
export POD_NAME=$(kubectl get pods -o go-template --template '{{range .items}}{{.metadata.name}}{{"\n"}}{{end}}')
echo Name of the Pod: $POD_NAME
```

ويمكنك الوصول إلى الحجيرة عبر API المارّ من الوكيل، بتشغيل:

```shell
curl http://localhost:8001/api/v1/namespaces/default/pods/$POD_NAME:8080/proxy/
```

ولكي يصبح النشر الجديد متاحاً دون استخدام الوكيل، يلزم وجود خدمة (Service)،
وسنشرحها في [الوحدة 4](/docs/tutorials/kubernetes-basics/expose/).
