Будь-хто може зробити внесок у Kubernetes. Що більшим стає ваш внесок у SIG Docs, то на вищі рівні членства в спільноті ви можете подавати заявку. Ці ролі дають змогу брати на себе більше відповідальності в спільноті. Кожна роль потребує більше часу та зобовʼязань. Ролі такі:

- Будь-хто: регулярні учасники документації Kubernetes
- Члени: можуть призначати й розглядати тікети, а також рецензувати pull request без обовʼязкової сили
- Рецензенти: можуть очолювати рецензування pull request до документації й ручатися за якість змін
- Затверджувачі: можуть очолювати рецензування документації та зливати зміни

<!-- body -->

## Будь-хто {#anyone}

Будь-хто з обліковим записом GitHub може зробити свій внесок у Kubernetes. SIG Docs вітає всіх нових учасників!

Будь-хто може:

- Створити тікет в будь-якому [репозиторії Kubernetes](https://github.com/kubernetes/), включаючи [`kubernetes/website`](https://github.com/kubernetes/website)
- Надавати відгуки на pull request без обовʼязкової сили
- Зробити внесок у локалізацію
- Запропонувати покращення у [Slack](https://slack.k8s.io/) або в [списку розсилки SIG docs](https://groups.google.com/forum/#!forum/kubernetes-sig-docs).

Після [підписання CLA](https://github.com/kubernetes/community/blob/main/CLA.md), будь-хто також може:

- Відкрити pull request, щоб покращити наявний вміст, додати новий вміст або написати допис у блог чи приклад використання
- Створювати діаграми, графічні ресурси, а також скринкасти й відео для вбудовування

Докладніше див. [Внесення нового вмісту](/docs/contribute/new-content/).

## Члени {#members}

Член — це хтось, хто подав кілька pull request до `kubernetes/website`. Члени є частиною [організації Kubernetes на GitHub](https://github.com/kubernetes).

Члени можуть:

- Робити все, що зазначено в розділі [Будь-хто](#anyone)
- Використовувати коментар `/lgtm`, щоб додати до pull request мітку LGTM (looks good to me)

  {{< note >}}
  Використання `/lgtm` запускає автоматизацію. Якщо ви хочете надати схвалення без обовʼязкової сили, коментар "LGTM" теж підійде!
  {{< /note >}}

- Використовувати коментар `/hold`, щоб заблокувати злиття pull request
- Використовувати коментар `/assign`, щоб призначити рецензента для pull request
- Рецензувати pull request без обовʼязкової сили
- Використовувати автоматизацію для розподілу та категоризації тікетів
- Документувати нові можливості

### Набуття членства {#becoming-a-member}

Після подання щонайменше 5 значних pull request та виконання інших [вимог](https://github.com/kubernetes/community/blob/main/community-membership.md#member):

1. Знайдіть двох [рецензентів](#reviewers) або [затверджувачів](#approvers), які стануть вашими [поручителями](/docs/contribute/advanced#sponsor-a-new-contributor).

   Попросіть поручительства в [каналі #sig-docs на Slack](https://kubernetes.slack.com) або в [списку розсилки SIG Docs](https://groups.google.com/forum/#!forum/kubernetes-sig-docs).

   {{< note >}}
   Не надсилайте прямий електронний лист або пряме повідомлення у Slack окремому члену SIG Docs. Ви повинні запитати про поручительство перед поданням вашої заявки на членство.
   {{< /note >}}

1. Відкрийте тікет на GitHub у репозиторії [`kubernetes/org`](https://github.com/kubernetes/org/). Використайте шаблон тікета **Organization Membership Request**.

1. Повідомте своїх поручителів про тікет на GitHub. Ви можете:
   - Згадати їхні імена користувачів GitHub у тікеті (`@<GitHub-username>`)
   - Надіслати їм посилання на тікет за допомогою Slack або електронної пошти.

     Поручителі схвалять ваш запит голосом `+1`. Щойно поручителі схвалять запит, адміністратор GitHub Kubernetes додасть вас як члена. Вітаємо!

     Якщо ваш запит на членство не приймається, ви отримаєте відгук. Після врахування відгуків подайте заявку знову.

1. Прийміть запрошення до організації Kubernetes на GitHub у своїй електронній пошті.

   {{< note >}}
   GitHub надсилає запрошення на стандартну електронну адресу вашого облікового запису.
   {{< /note >}}

## Рецензенти {#reviewers}

Рецензенти відповідають за рецензування відкритих pull request. На відміну від відгуків членів, відгуки рецензентів автор PR має враховувати. Рецензенти є членами команди GitHub [@kubernetes/sig-docs-{language}-reviews](https://github.com/orgs/kubernetes/teams?query=sig-docs).

Рецензенти можуть:

- Робити все, що зазначено в розділах [Будь-хто](#anyone) та [Члени](#members)
- Рецензувати pull request і надавати відгуки з обовʼязковою силою

  {{< note >}}
  Щоб надати відгук без обовʼязкової сили, починайте коментарі з фрази на кшталт "Optionally: ".
  {{< /note >}}

- Редагувати в коді рядки, які бачать користувачі
- Покращувати коментарі до коду

Ви можете бути рецензентом SIG Docs або рецензентом для документів у певній предметній області.

### Призначення рецензентів до pull request {#assigning-reviewers-to-pull-requests}

Автоматизація призначає рецензентів для всіх pull request. Ви можете попросити про рецензію конкретну людину, залишивши коментар: `/assign [@_github_handle]`.

Якщо призначений рецензент не прокоментував PR, за справу може взятися інший рецензент. За потреби також можна призначати технічних рецензентів.

### Використання `/lgtm` {#using-lgtm}

LGTM означає "Looks good to me" (на мою думку, усе добре) і вказує, що pull request технічно точний і готовий до злиття. Для злиття всі PR потребують коментаря `/lgtm` від рецензента та коментаря `/approve` від затверджувача.

Коментар `/lgtm` від рецензента має обовʼязкову силу й запускає автоматизацію, яка додає мітку `lgtm`.

### Як стати рецензентом {#becoming-a-reviewer}

Коли ви відповідаєте [вимогам](https://github.com/kubernetes/community/blob/main/community-membership.md#reviewer), ви можете стати рецензентом SIG Docs. Рецензенти в інших SIG повинні подавати окрему заявку на статус рецензента в SIG Docs.

Щоб подати заявку:

1. Відкрийте pull request, що додає ваше імʼя користувача GitHub до розділу файлу [OWNERS_ALIASES](https://github.com/kubernetes/website/blob/main/OWNERS_ALIASES) в репозиторії `kubernetes/website`.

   {{< note >}}
   Якщо ви не впевнені, де себе додати, додайте себе до `sig-docs-en-reviews`.
   {{< /note >}}

1. Призначте PR одному або кільком затверджувачам SIG Docs (імена користувачів вказані в `sig-docs-{language}-owners`).

Якщо заявку схвалено, лідер SIG Docs додає вас до відповідної команди GitHub. Після додавання [K8s-ci-robot](https://github.com/kubernetes/test-infra/tree/master/prow#bots-home) призначає та пропонує вас як рецензента на нові pull request.

## Затверджувачі {#approvers}

Затверджувачі рецензують і затверджують pull request для злиття. Затверджувачі є членами команд GitHub [@kubernetes/sig-docs-{language}-owners](https://github.com/orgs/kubernetes/teams/?query=sig-docs).

Затверджувачі можуть:

- Все, що зазначено в розділах [Будь-хто](#anyone), [Члени](#members) та [Рецензенти](#reviewers)
- Публікувати вміст учасників, затверджуючи та зливаючи pull request за допомогою коментаря `/approve`
- Пропонувати покращення до посібника зі стилю
- Пропонувати покращення до тестів документації
- Пропонувати покращення до вебсайту Kubernetes або інших інструментів

Якщо PR уже має `/lgtm` або затверджувач також залишає коментар `/lgtm`, PR зливається автоматично. Затверджувач SIG Docs має залишати `/lgtm` лише на змінах, які не потребують додаткового технічного рецензування.

### Затвердження pull request {#approving-pull-requests}

Лише затверджувачі та лідери SIG Docs можуть зливати pull request у репозиторій вебсайту. Це передбачає певні обовʼязки.

- Затверджувачі можуть використовувати команду `/approve`, яка зливає PR в репозиторій.

  {{< warning >}}
  Недбале злиття може зламати сайт, тож, зливаючи щось, будьте певні свого рішення.
  {{< /warning >}}

- Переконайтеся, що запропоновані зміни відповідають [посібнику з вмісту документації](/docs/contribute/style/content-guide/).

  Якщо у вас виникає запитання або ви в чомусь не впевнені, сміливо просіть про додаткове рецензування.

- Перш ніж застосувати `/approve` до PR, переконайтеся, що тести Netlify пройшли.

  <img src="/images/docs/contribute/netlify-pass.png" width="75%" alt="Тести Netlify мають пройти до затвердження" />

- Відвідайте попередній перегляд сторінки Netlify для PR, щоб переконатися, що все виглядає добре перед затвердженням.

- Беріть участь у [графіку чергування відповідальних за PR](https://github.com/kubernetes/website/wiki/PR-Wranglers) з тижневими змінами. SIG Docs очікує, що всі затверджувачі братимуть участь у цьому чергуванні. Докладніше див. [Відповідальні за PR](/docs/contribute/participate/pr-wranglers/).

### Як стати затверджувачем {#becoming-an-approver}

Коли ви відповідаєте [вимогам](https://github.com/kubernetes/community/blob/main/community-membership.md#approver), ви можете стати затверджувачем SIG Docs. Затверджувачі в інших SIG повинні подавати окрему заявку на статус затверджувача в SIG Docs.

Щоб подати заявку:

1. Відкрийте pull request, що додає вас до розділу файлу [OWNERS_ALIASES](https://github.com/kubernetes/website/blob/main/OWNERS_ALIASES) у репозиторії `kubernetes/website`.

   {{< note >}}
   Якщо ви не впевнені, де себе додати, додайте себе до `sig-docs-en-owners`.
   {{< /note >}}

2. Призначте PR одному або кільком поточним затверджувачам SIG Docs.

Якщо заявку схвалено, лідер SIG Docs додає вас до відповідної команди GitHub. Після додавання, [@k8s-ci-robot](https://github.com/kubernetes/test-infra/tree/master/prow#bots-home) призначає та пропонує вас як рецензента на нові pull request.
