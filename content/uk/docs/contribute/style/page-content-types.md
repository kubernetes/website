Документація Kubernetes містить кілька типів контенту сторінок:

- Concept (концепція)
- Task (Завдання)
- Tutorial (підручник)
- Reference (Довідка)

Як довідковий матеріал щодо того, як писати сторінки кожного з цих типів, вам також може стати в пригоді фреймворк документації [Diátaxis](https://diataxis.fr/).

<!-- body -->

## Розділи контенту {#content-sections}

Кожен тип контенту сторінок містить кілька розділів, визначених коментарями Markdown і HTML-заголовками. Ви можете додати заголовки контенту до вашої сторінки за допомогою shortcode `heading`. Коментарі та заголовки допомагають підтримувати структуру типів контенту сторінок.

Приклади коментарів Markdown, що визначають розділи контенту сторінки:

```markdown
<!-- overview -->
```

```markdown
<!-- body -->
```

Щоб створити загальні заголовки на сторінках вмісту, використовуйте shortcode `heading` із рядком заголовка.

Приклади рядків заголовків:

- whatsnext
- prerequisites
- objectives
- cleanup
- synopsis
- seealso
- options

Наприклад, щоб створити заголовок `whatsnext`, додайте shortcode із рядком "whatsnext":

```none
## {{%/* heading "whatsnext" */%}}
```

Заголовок `prerequisites` можна оголосити так:

```none
## {{%/* heading "prerequisites" */%}}
```

Shortcode `heading` очікує один строковий параметр. Рядок заголовка відповідає префіксу змінної у файлах `i18n/<lang>/<lang>.toml`. Наприклад:

`i18n/en/en.toml`:

```toml
[whatsnext_heading]
other = "What's next"
```

`i18n/ko/ko.toml`:

```toml
[whatsnext_heading]
other = "다음 내용"
```

## Типи контенту {#content-types}

Кожен тип контенту неформально визначає свою очікувану структуру сторінки. Створюйте контент сторінки, використовуючи рекомендовані розділи сторінок.

### Концепція {#concept}

Сторінка концепції пояснює певний аспект Kubernetes. Наприклад, сторінка концепції може описувати обʼєкт Kubernetes Deployment і пояснювати його роль як застосунку після розгортання, масштабування та оновлення. Зазвичай сторінки концепцій не містять послідовностей кроків, а натомість надають посилання на завдання або підручники.

Щоб написати нову сторінку концепції, створіть файл Markdown у підтеці теки `/content/en/docs/concepts` з такими характеристиками:

Сторінки концепцій поділяються на три розділи:

| Розділ сторінки|
|---------------|
| overview |
| body |
| whatsnext |

Розділи `overview` і `body` зʼявляються як коментарі на сторінці концепції. Розділ `whatsnext` можна додати на сторінку за допомогою shortcode `heading`.

Заповніть кожен розділ контентом. Дотримуйтесь цих вказівок:

- Організуйте контент за допомогою заголовків H2 і H3.
- Для розділу `overview` задайте контекст теми одним абзацом.
- У розділі `body` поясніть концепцію.
- У розділі `whatsnext` наведіть маркований список тем (не більше 5), щоб дізнатися більше про концепцію.

[Анотації](/docs/concepts/overview/working-with-objects/annotations/) — це опублікований приклад сторінки концепції.

### Завдання {#task}

Сторінка завдання показує, як зробити щось одне, зазвичай через коротку послідовність кроків. Сторінки завдань містять мінімум пояснень, але часто надають посилання на концептуальні теми з відповідним підґрунтям і знаннями.

Щоб написати нову сторінку завдання, створіть файл Markdown у підтеці `/content/en/docs/tasks` з такими характеристиками:

| Розділ сторінки|
|----------------|
| overview       |
| prerequisites  |
| steps          |
| discussion     |
| whatsnext      |

Розділи `overview`, `steps` і `discussion` зʼявляються як коментарі на сторінці завдання. Ви можете додати розділи `prerequisites` і `whatsnext` на вашу сторінку за допомогою shortcode `heading`.

У кожному розділі напишіть ваш контент, використовуючи такі вказівки:

- Використовуйте щонайменше заголовки H2 (з двома символами `#` на початку). Самі розділи отримують заголовки автоматично від шаблону.
- У розділі `overview` використайте абзац, щоб задати контекст для всієї теми. Коротко поясніть, чому читач може захотіти виконати це завдання (мотивація або сценарій використання), щоб він міг вирішити, чи стосується його сторінка, ще до читання кроків.
- У розділі `prerequisites` за можливості використовуйте марковані списки. Додаткові передумови починайте додавати під `include`. Стандартні передумови включають працюючий кластер Kubernetes.
- У розділі `steps` використовуйте нумеровані списки. Зосередьтеся на самому завданні. Якщо крок потребує значного підґрунтя, дайте посилання на відповідну сторінку концепції замість того, щоб повторювати пояснення тут.
- У розділі `discussion` використовуйте звичайний контент для розширення інформації, про яку йдеться у розділі `steps`.
- У розділі `whatsnext` наведіть маркований список із не більше ніж 5 тем, які читач, можливо, захоче прочитати далі.

Приклад опублікованої теми-завдання — [Використання HTTP-проксі для доступу до Kubernetes API](/docs/tasks/extend-kubernetes/http-proxy-access-api/).

### Підручник {#tutorial}

Сторінка підручника показує, як досягти мети, більшої за одне завдання. Зазвичай сторінка підручника має кілька розділів, кожен із яких містить послідовність кроків. Наприклад, підручник може містити покроковий розбір прикладу коду, що ілюструє певну можливість Kubernetes. Підручники можуть містити поверхневі пояснення, але для глибоких пояснень мають посилатися на повʼязані концептуальні теми.

Щоб написати нову сторінку підручника, створіть файл Markdown у підтеці теки `/content/en/docs/tutorials` з такими характеристиками:

| Розділ сторінки|
|---------------|
| overview      |
| prerequisites |
| objectives    |
| lessoncontent |
| cleanup       |
| whatsnext     |

Розділи `overview`, `objectives` і `lessoncontent` зʼявляються як коментарі на сторінці підручника. Розділи `prerequisites`, `cleanup` і `whatsnext` можна додати на сторінку за допомогою shortcode `heading`.

У кожному розділі напишіть ваш контент, використовуючи такі вказівки:

- Використовуйте щонайменше заголовки H2 (з двома символами `#` на початку). Самі розділи отримують заголовки автоматично від шаблону.
- У розділі `overview` використовуйте абзац для встановлення контексту для всієї теми.
- У розділі `prerequisites` за можливості використовуйте марковані списки. Додаткові передумови додавайте після тих, що включені стандартно.
- У розділі `objectives` використовуйте марковані списки.
- У розділі `lessoncontent` поєднуйте нумеровані списки й розповідний вміст відповідно до потреби.
- У розділі `cleanup` використовуйте нумеровані списки, щоб описати кроки очищення стану кластера після виконання завдання.
- У розділі `whatsnext` наведіть маркований список із не більше ніж 5 тем, які читач, можливо, захоче прочитати далі.

Приклад опублікованої теми-підручника — [Запуск застосунку без збереження стану за допомогою Deployment](/docs/tasks/run-application/run-stateless-application-deployment/).

### Довідка {#reference}

Сторінка довідки інструмента компонента показує опис і параметри прапорців для інструмента компонента Kubernetes. Кожна сторінка генерується зі скриптів із використанням команд інструмента компонента.

Сторінка довідки з інструмента має кілька можливих розділів:

| Розділ сторінки |
|------------------------------|
| synopsis |
| options|
| options from parent commands |
| examples |
| seealso|

Приклади опублікованих сторінок довідки з інструмента:

- [kubeadm init](/docs/reference/setup-tools/kubeadm/kubeadm-init/)
- [kube-apiserver](/docs/reference/command-line-tools-reference/kube-apiserver/)
- [kubectl](/docs/reference/kubectl/kubectl/)
