Цей сайт використовує Hugo. У Hugo [організація вмісту](https://gohugo.io/content-management/organization/) — одне з ключових понять.

<!-- body -->

{{% note %}}
**Порада щодо Hugo:** для сеансів редагування вмісту запускайте Hugo командою `hugo server --navigateToChanged`.
{{% /note %}}

## Списки сторінок {#page-lists}

### Порядок сторінок {#page-order}

Бічне меню документації, браузер сторінок документації тощо впорядковуються за стандартним порядком сортування Hugo: за вагою (від 1), датою (спершу новіші) і, нарешті, за заголовком посилання.

Тож, якщо ви хочете перемістити сторінку або розділ вище, задайте вагу у front matter сторінки:

```yaml
title: My Page
weight: 10
```

{{% note %}}
Для ваги сторінок розумно використовувати не 1, 2, 3 ..., а інший інтервал, скажімо, 10, 20, 30... Це дасть змогу згодом вставляти сторінки там, де потрібно. Крім того, ваги в межах однієї теки (розділу) не мають збігатися з іншими вагами. Так вміст завжди буде впорядковано правильно, особливо в локалізованому вмісті.
{{% /note %}}

### Головне меню документації {#documentation-main-menu}

Головне меню `Документація` формується з розділів у `docs/`, у front matter файлу вмісту розділу `_index.md` яких встановлено прапорець `main_menu`:

```yaml
main_menu: true
```

Зверніть увагу, що заголовок посилання береться з `linkTitle` сторінки, тож якщо ви хочете, щоб він відрізнявся від заголовка, змініть його у файлі вмісту:

```yaml
main_menu: true
title: Page Title
linkTitle: Title used in links
```

{{% note %}}
Це потрібно зробити для кожної мови. Якщо ви не бачите свого розділу в меню, імовірно, Hugo не визначає його як розділ. Створіть файл вмісту `_index.md` у теці розділу.
{{% /note %}}

### Бічне меню документації {#documentation-side-menu}

Бічне меню документації формується з _поточного дерева розділів_, починаючи нижче `docs/`.

У ньому відображаються всі розділи та їхні сторінки.

Якщо ви не хочете показувати розділ або сторінку в списку, встановіть прапорець `toc_hide` у `true` у front matter:

```yaml
toc_hide: true
```

Коли ви переходите до розділу, що має вміст, показується конкретний розділ або сторінка (наприклад, `_index.md`). Інакше показується перша сторінка в цьому розділі.

### Браузер документації {#documentation-browser}

Браузер сторінок на домашній сторінці документації формується з усіх розділів і сторінок, розміщених безпосередньо нижче `docs section`.

Якщо ви не хочете показувати розділ або сторінку в списку, встановіть прапорець `toc_hide` у `true` у front matter:

```yaml
toc_hide: true
```

### Головне меню {#the-main-menu}

Посилання сайту в меню вгорі праворуч (а також у нижньому колонтитулі) формуються через пошук сторінок. Так забезпечується, що сторінка справді існує. Тож якщо розділу `case-studies` на сайті (для мови) немає, посилання на нього не буде.

## Пакети сторінок {#page-bundles}

Крім окремих сторінок вмісту (файлів Markdown), Hugo підтримує [пакети сторінок](https://gohugo.io/content-management/page-bundles/).

Один із прикладів — [Власні shortcodes Hugo](/docs/contribute/style/hugo-shortcodes/). Це `leaf bundle`. Усе, що міститься в цій теці, зокрема `index.md`, буде частиною пакета. Це також стосується посилань відносно сторінки, зображень, які можна обробляти, тощо:

```bash
en/docs/home/contribute/includes
├── example1.md
├── example2.md
├── index.md
└── podtemplate.json
```

Ще один поширений приклад — пакет `includes`. У його front matter встановлено `headless: true`, тобто він не отримує власного URL. Він використовується лише в інших сторінках.

```bash
en/includes
├── default-storage-class-prereqs.md
├── index.md
├── partner-script.js
├── partner-style.css
├── task-tutorial-prereqs.md
├── user-guide-content-moved.md
└── user-guide-migration-notice.md
```

Кілька важливих приміток щодо файлів у пакетах:

* Для перекладених пакетів відсутні файли, що не є вмістом, успадковуються з мов вище. Це дає змогу уникнути дублювання.
* Усі файли в пакеті — це те, що Hugo називає `Resources`, і для кожної мови можна надати метадані, як-от параметри й заголовок, навіть якщо файл не підтримує front matter (файли YAML тощо). Див. [Метадані ресурсів сторінок](https://gohugo.io/content-management/page-resources/#page-resources-metadata).
* Значення, отримане з `.RelPermalink` ресурсу `Resource`, є відносним до сторінки. Див. [Permalinks](https://gohugo.io/content-management/urls/#permalinks).
