## Постійне сховище {#storage}

У Windows є багатошаровий драйвер файлової системи для монтування шарів контейнера та створення копії файлової системи на основі NTFS. Усі шляхи файлів у контейнері розвʼязуються лише в контексті цього контейнера.

* У Docker монтування томів може бути спрямоване лише на теку в контейнері, а не на окремий файл. Це обмеження не стосується containerd.
* Монтування томів не може проєктувати файли або теки назад на файлову систему хоста.
* Файлові системи лише для читання не підтримуються, оскільки завжди потрібен доступ для запису до реєстру Windows та бази даних SAM. Однак томи лише для читання підтримуються.
* Маски користувача та дозволи для томів недоступні. Оскільки SAM не є спільним для хоста й контейнера, між ними немає зіставлення. Усі дозволи розвʼязуються в контексті контейнера.

Як наслідок, на вузлах Windows не підтримуються такі можливості сховища:

* Монтування підшляхів тому: у контейнері Windows можна змонтувати лише весь том
* Монтування підшляхів тому для Secrets
* Проєкція монтування хоста
* Коренева файлова система лише для читання (зіставлені томи все ще підтримують `readOnly`)
* Зіставлення блокових пристроїв
* Памʼять як носій сховища (наприклад, `emptyDir.medium` зі значенням `Memory`)
* Можливості файлової системи, такі як uid/gid; дозволи файлової системи Linux для кожного користувача
* Встановлення [дозволів Secret за допомогою DefaultMode](/docs/tasks/inject-data-application/distribute-credentials-secure/#set-posix-permissions-for-secret-keys) (через залежність від UID/GID)
* Підтримка сховища/томів на основі NFS
* Розширення змонтованого тому (resizefs)

{{< glossary_tooltip text="Томи" term_id="volume" >}} Kubernetes дозволяють розгортати в Kubernetes складні застосунки, яким потрібне збереження даних і спільне використання томів Podʼами. Керування постійними томами, повʼязаними з конкретним бекендом сховища або протоколом, включає такі дії, як надання, скасування надання та зміна розміру томів, підʼєднання тому до вузла Kubernetes і відʼєднання від нього, а також монтування тому в окремих контейнерах Podʼа, якому потрібно зберігати дані, і його розмонтування.

Компоненти керування томами постачаються як [втулки](/docs/concepts/storage/volumes/#volume-types) томів Kubernetes. У Windows підтримуються такі широкі класи втулків томів Kubernetes:

* [Втулки FlexVolume](/docs/concepts/storage/volumes/#flexvolume)
  * Зверніть увагу, що FlexVolumes застаріли з версії 1.23
* [Втулки CSI](/docs/concepts/storage/volumes/#csi)
