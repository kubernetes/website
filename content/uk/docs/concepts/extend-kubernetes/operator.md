<!-- overview -->

Оператори — це програмні розширення Kubernetes, які використовують [власні ресурси](/docs/concepts/extend-kubernetes/api-extension/custom-resources/) для керування застосунками та їхніми компонентами. Оператори дотримуються принципів Kubernetes, зокрема [циклу управління](/docs/concepts/architecture/controller).

<!-- body -->

## Мотивація {#motivation}

_Шаблон Operator_ має на меті відтворити ключову мету людини-оператора, яка керує сервісом або набором сервісів. Люди-оператори, які відповідають за конкретні застосунки та сервіси, мають глибокі знання про те, як система повинна поводитися, як її розгортати та як реагувати на проблеми.

Люди, які запускають робочі навантаження в Kubernetes, часто воліють використовувати автоматизацію для виконання повторюваних завдань. Шаблон Operator показує, як написати код для автоматизації завдання понад те, що надає сам Kubernetes.

## Оператори в Kubernetes {#operators-in-kubernetes}

Kubernetes створений для автоматизації. Із коробки ви отримуєте багато вбудованої автоматизації від ядра Kubernetes. Ви можете використовувати Kubernetes для автоматизації розгортання та запуску робочих навантажень, *і* ви можете автоматизувати те, як це робить Kubernetes.

Концепція {{< glossary_tooltip text="шаблону Operator" term_id="operator-pattern" >}} Kubernetes дозволяє розширити поведінку кластера без зміни коду самого Kubernetes, повʼязавши {{< glossary_tooltip text="контролери" term_id="controller" >}} з одним або кількома власними ресурсами. Оператори є клієнтами API Kubernetes, які діють як контролери для [власного ресурсу](/docs/concepts/extend-kubernetes/api-extension/custom-resources/).

## Приклад оператора {#example}

Деякі завдання, які можна автоматизувати за допомогою оператора, включають:

* розгортання застосунку за запитом
* створення та відновлення резервних копій стану цього застосунку
* оброблення оновлень коду застосунку разом із повʼязаними змінами, такими як схеми баз даних або додаткові параметри конфігурації
* публікація Service для застосунків, які не підтримують API Kubernetes для їх виявлення
* імітація відмови в усьому кластері або його частині для перевірки його стійкості
* обрання лідера для розподіленого застосунку без внутрішнього процесу виборів учасників

Як може виглядати оператор докладніше? Ось приклад:

1. Власний ресурс з назвою SampleDB, який можна налаштувати в кластері.
2. Deployment, який забезпечує роботу Podʼа, що містить контролерну частину оператора.
3. Образ контейнера з кодом оператора.
4. Код контролера, який надсилає запити до панелі управління, щоб дізнатися, які ресурси SampleDB налаштовано.
5. Ядром оператора є код, який підказує API-серверу, як привести реальний стан у відповідність до налаштованих ресурсів.
   * Якщо ви додаєте новий SampleDB, оператор налаштовує PersistentVolumeClaims для надійного сховища бази даних, StatefulSet для запуску SampleDB та Job для початкової конфігурації.
   * Якщо ви видаляєте його, оператор робить знімок, а потім переконується, що StatefulSet і томи також видалено.
6. Оператор також керує регулярним резервним копіюванням бази даних. Для кожного ресурсу SampleDB оператор визначає, коли створити Pod, який може підʼєднатися до бази даних і зробити резервні копії. Ці Podʼи покладаються на ConfigMap та/або Secret, що містить параметри підʼєднання до бази даних та облікові дані.
7. Оскільки оператор має на меті надійну автоматизацію ресурсу, яким він керує, у ньому буде додатковий допоміжний код. У цьому прикладі код перевіряє, чи працює база даних на старій версії, і якщо так, створює обʼєкти Job, які оновлюють її для вас.

## Розгортання операторів {#deploying-operators}

Найпоширеніший спосіб розгортання оператора — додавання CustomResourceDefinition та повʼязаного з ним контролера до вашого кластера. Контролер зазвичай працює за межами {{< glossary_tooltip text="панелі управління" term_id="control-plane" >}}, так само як і будь-який контейнеризований застосунок. Наприклад, ви можете запустити контролер у своєму кластері як Deployment.

## Використання операторів {#using-operators}

Після розгортання оператора ви використовуєте його, додаючи, змінюючи або видаляючи ресурси того виду, який використовує оператор. Продовжуючи наведений вище приклад, ви налаштуєте Deployment для самого оператора, а потім:

```shell
kubectl get SampleDB                   # пошук налаштованих баз даних

kubectl edit SampleDB/example-database # ручна зміна деяких параметрів
```

&hellip;і все! Оператор подбає про застосування змін, а також про підтримання наявного сервісу в належному стані.

## Створення власних операторів {#writing-operator}

Якщо в екосистемі немає оператора, який реалізує потрібну вам поведінку, ви можете створити власний.

Ви також можете реалізувати оператор (тобто контролер) будь-якою мовою або в будь-якому середовищі виконання, що може діяти як [клієнт API Kubernetes](/docs/reference/using-api/client-libraries/).

Нижче наведено кілька бібліотек та інструментів, які можна використовувати для написання власного оператора cloud native.
