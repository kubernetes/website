Ця документація присвячена дослідженню й діагностиці проблем, повʼязаних з {{<glossary_tooltip text="kubectl" term_id="kubectl">}}. Якщо у вас виникли проблеми з доступом до `kubectl` або підʼєднанням до кластера, цей документ описує різні поширені сценарії та можливі рішення, які допоможуть визначити й усунути ймовірну причину.

<!-- body -->

## {{% heading "prerequisites" %}} {#before-you-begin}

* Вам потрібно мати кластер Kubernetes.
* Вам також потрібно встановити `kubectl` — дивіться [встановлення інструментів](/docs/tasks/tools/#kubectl)

## Перевірка налаштувань kubectl {#verify-kubectl-setup}

Переконайтеся, що ви правильно встановили та налаштували `kubectl` на вашому локальному компʼютері. Перевірте версію `kubectl`, щоб впевнитися, що вона актуальна та сумісна з вашим кластером.

Перевірка версії kubectl:

```shell
kubectl version
```

Ви побачите подібний вивід:

```console
Client Version: version.Info{Major:"1", Minor:"27", GitVersion:"v1.27.4",GitCommit:"fa3d7990104d7c1f16943a67f11b154b71f6a132", GitTreeState:"clean",BuildDate:"2023-07-19T12:20:54Z", GoVersion:"go1.20.6", Compiler:"gc", Platform:"linux/amd64"}
Kustomize Version: v5.0.1
Server Version: version.Info{Major:"1", Minor:"27", GitVersion:"v1.27.3",GitCommit:"25b4e43193bcda6c7328a6d147b1fb73a33f1598", GitTreeState:"clean",BuildDate:"2023-06-14T09:47:40Z", GoVersion:"go1.20.5", Compiler:"gc", Platform:"linux/amd64"}

```

Якщо замість `Server Version` ви бачите `Unable to connect to the server: dial tcp <server-ip>:8443: i/o timeout`, вам потрібно усунути проблеми зі зʼєднанням kubectl з кластером.

Переконайтеся, що ви встановили kubectl, слідуючи [офіційній документації з встановлення kubectl](/docs/tasks/tools/#kubectl), і правильно налаштували змінну середовища `$PATH`.

## Перевірка kubeconfig {#check-kubeconfig}

`kubectl` потребує файлу `kubeconfig` для підʼєднання до кластера Kubernetes. Файл `kubeconfig` зазвичай розташований у `~/.kube/config`. Переконайтеся, що у вас є дійсний файл `kubeconfig`. Якщо у вас немає файлу `kubeconfig`, його можна отримати в адміністратора Kubernetes або скопіювати з `/etc/kubernetes/admin.conf` на панелі управління Kubernetes. Якщо ви розгорнули кластер Kubernetes на хмарній платформі й втратили файл `kubeconfig`, його можна згенерувати знову за допомогою інструментів вашого хмарного провайдера. Як згенерувати файл `kubeconfig` знову, дивіться в документації хмарного провайдера.

Перевірте, чи правильно налаштовано змінну середовища `$KUBECONFIG`. Ви можете встановити змінну середовища `$KUBECONFIG` або використовувати параметр `--kubeconfig` з kubectl, щоб вказати теку файлу `kubeconfig`.

## Перевірка зʼєднання VPN {#check-vpn-connectivity}

Якщо ви використовуєте віртуальну приватну мережу (VPN) для доступу до кластера Kubernetes, переконайтеся, що зʼєднання VPN активне й стабільне. Іноді розриви зʼєднання VPN можуть спричинити проблеми зі зʼєднанням з кластером. Знову підʼєднайтеся до VPN і спробуйте ще раз отримати доступ до кластера.

## Автентифікація та авторизація {#authentication-and-authorization}

Якщо ви використовуєте автентифікацію на базі токенів і kubectl повертає помилку щодо автентифікаційного токена або адреси сервера автентифікації, перевірте, що токен автентифікації Kubernetes та адреса сервера автентифікації налаштовані правильно.

Якщо kubectl повертає помилку щодо авторизації, переконайтеся, що ви використовуєте дійсні облікові дані користувача і маєте дозвіл на доступ до запитаного ресурсу.

## Перевірка контекстів {#verify-contexts}

Kubernetes підтримує роботу з [кількома кластерами та контекстами](/docs/tasks/access-application-cluster/configure-access-multiple-clusters/). Переконайтеся, що ви використовуєте правильний контекст для взаємодії з вашим кластером.

Виведіть доступні контексти:

```shell
kubectl config get-contexts
```

Перемкніться на потрібний контекст:

```shell
kubectl config use-context <context-name>
```

## API-сервер і балансувальник навантаження {#api-server-and-load-balancer}

Сервер {{<glossary_tooltip text="kube-apiserver" term_id="kube-apiserver">}} — центральний компонент кластера Kubernetes. Якщо API-сервер або балансувальник навантаження перед вашими API-серверами недоступний чи не відповідає, ви не зможете взаємодіяти з кластером.

Перевірте командою `ping`, чи доступний хост API-сервера. Перевірте мережеве зʼєднання кластера й фаєрвол. Якщо ви розгортали кластер у хмарного провайдера, перевірте статус перевірки справності API-сервера кластера у вашого хмарного провайдера.

Перевірте стан балансувальника навантаження (якщо він використовується), щоб переконатися, що він справний і передає трафік на API-сервер.

## Проблеми з TLS {#tls-problems}

* Потрібні додаткові інструменти — `base64` та `openssl` версії 3.0 або вище.

Стандартно API-сервер Kubernetes обслуговує лише запити HTTPS. Тож проблеми з TLS можуть виникати з різних причин, наприклад через закінчення строку дії сертифіката або недійсність ланцюга довіри.

Сертифікат TLS можна знайти у файлі kubeconfig, розташованому в `~/.kube/config`. Атрибут `certificate-authority` містить сертифікат CA, а атрибут `client-certificate` — клієнтський сертифікат.

Перевірте строк дії цих сертифікатів:

```shell
kubectl config view --flatten --output 'jsonpath={.clusters[0].cluster.certificate-authority-data}' | base64 -d | openssl x509 -noout -dates
```

вивід:

```console
notBefore=Feb 13 05:57:47 2024 GMT
notAfter=Feb 10 06:02:47 2034 GMT
```

```shell
kubectl config view --flatten --output 'jsonpath={.users[0].user.client-certificate-data}'| base64 -d | openssl x509 -noout -dates
```

вивід:

```console
notBefore=Feb 13 05:57:47 2024 GMT
notAfter=Feb 12 06:02:50 2025 GMT
```

## Перевірка допоміжних інструментів kubectl {#verify-kubectl-helpers}

Деякі допоміжні інструменти автентифікації kubectl спрощують доступ до кластерів Kubernetes. Якщо ви використовували такі інструменти й маєте проблеми зі зʼєднанням, переконайтеся, що потрібні налаштування досі на місці.

Перевірте конфігурацію kubectl щодо даних автентифікації:

```shell
kubectl config view
```

Якщо раніше ви використовували допоміжний інструмент (наприклад, `kubectl-oidc-login`), переконайтеся, що він все ще встановлений і правильно налаштований.
