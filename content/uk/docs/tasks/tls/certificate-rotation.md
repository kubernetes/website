## Огляд {#overview}

kubelet використовує сертифікати для автентифікації в API Kubernetes. Стандартно ці сертифікати видаються на один рік, щоб їх не потрібно було оновлювати надто часто.

Kubernetes містить [ротацію сертифікатів kubelet](/docs/reference/access-authn-authz/kubelet-tls-bootstrapping/), яка автоматично генерує новий ключ і запитує новий сертифікат в API Kubernetes, коли строк дії поточного сертифіката наближається до завершення. Щойно новий сертифікат стане доступним, він використовуватиметься для автентифікації зʼєднань з API Kubernetes.

## Увімкнення ротації клієнтських сертифікатів {#enabling-client-certificate-rotation}

Процес `kubelet` приймає аргумент `--rotate-certificates`, який визначає, чи автоматично kubelet запитуватиме новий сертифікат, коли наближається завершення строку дії поточного сертифіката.

Процес `kube-controller-manager` приймає аргумент `--cluster-signing-duration` (`--experimental-cluster-signing-duration` до версії 1.19), який визначає, на який строк видаватимуться сертифікати.

## Розуміння налаштувань ротації сертифікатів {#understanding-the-certificate-rotation-configuration}

Якщо під час запуску kubelet налаштований на початкове завантаження (за допомогою прапорця `--bootstrap-kubeconfig`), він використає свій початковий сертифікат, щоб підʼєднатися до API Kubernetes і надіслати запит на підписання сертифіката. Переглянути стан запитів на підписання сертифікатів можна за допомогою:

```sh
kubectl get csr
```

Спочатку запит на підписання сертифіката від kubelet на вузлі матиме статус `Pending`. Якщо запит відповідає певним критеріям, менеджер контролерів автоматично схвалить його, і він матиме статус `Approved`. Далі менеджер контролерів підпише сертифікат, виданий на строк, вказаний параметром `--cluster-signing-duration`, і підписаний сертифікат буде прикріплено до запиту на підписання сертифіката.

kubelet отримає підписаний сертифікат з API Kubernetes і запише його на диск у місце, вказане в `--cert-dir`. Потім kubelet використовуватиме новий сертифікат для підʼєднання до API Kubernetes.

Коли наближається завершення строку дії підписаного сертифіката, kubelet автоматично надсилає новий запит на підписання сертифіката через API Kubernetes. Це може статися в будь-який момент, коли лишається від 30% до 10% строку дії сертифіката. Менеджер контролерів знову автоматично схвалює запит на сертифікат і прикріплює підписаний сертифікат до запиту на підписання сертифіката. kubelet отримує новий підписаний сертифікат з API Kubernetes і записує його на диск. Потім він оновлює свої зʼєднання з API Kubernetes, щоб перепідʼєднатися з новим сертифікатом.
