На цій сторінці показано, як налаштувати спільний простір імен процесів для Podʼа. Коли спільний простір імен процесів увімкнено, процеси в контейнері видимі для всіх інших контейнерів у тому самому Podʼі.

Цю можливість можна використовувати для налаштування взаємодійних контейнерів, як-от sidecar-контейнер обробника логів, або для усунення несправностей образів контейнерів, які не містять утиліт налагодження, наприклад оболонки.

## Налаштування Podʼа {#configure-a-pod}

Спільний простір імен процесів вмикається за допомогою поля `shareProcessNamespace` у `.spec` Podʼа. Наприклад:

{{% code_sample file="pods/share-process-namespace.yaml" %}}

1. Створіть Pod `nginx` у вашому кластері:

   ```shell
   kubectl apply -f https://k8s.io/examples/pods/share-process-namespace.yaml
   ```

1. Підʼєднайтеся до контейнера `shell` і запустіть `ps`:

   ```shell
   kubectl exec -it nginx -c shell -- /bin/sh
   ```

   Якщо ви не бачите запрошення командного рядка, спробуйте натиснути Enter. В оболонці контейнера:

   ```shell
   # виконайте це в контейнері "shell"
   ps ax
   ```

   Вивід подібний до такого:

   ```none
   PID   USER     TIME  COMMAND
       1 root      0:00 /pause
       8 root      0:00 nginx: master process nginx -g daemon off;
      14 101       0:00 nginx: worker process
      15 root      0:00 sh
      21 root      0:00 ps ax
   ```

Можна надсилати сигнали процесам в інших контейнерах. Наприклад, надішліть `SIGHUP` до `nginx`, щоб перезапустити робочий процес. Для цього потрібна можливість `SYS_PTRACE`.

```shell
# виконайте це в контейнері "shell"
kill -HUP 8   # змініть "8" на PID головного процесу nginx, якщо потрібно
ps ax
```

Вивід подібний до такого:

```none
PID   USER     TIME  COMMAND
    1 root      0:00 /pause
    8 root      0:00 nginx: master process nginx -g daemon off;
   15 root      0:00 sh
   22 101       0:00 nginx: worker process
   23 root      0:00 ps ax
```

Можна навіть отримати доступ до файлової системи іншого контейнера через посилання `/proc/$pid/root`.

```shell
# виконайте це в контейнері "shell"
# змініть "8" на PID процесу Nginx, якщо потрібно
head /proc/8/root/etc/nginx/nginx.conf
```

Вивід подібний до такого:

```none
user  nginx;
worker_processes  1;

error_log  /var/log/nginx/error.log warn;
pid        /var/run/nginx.pid;


events {
    worker_connections  1024;
```

## Розуміння спільного простору імен процесів {#understanding-process-namespace-sharing}

Podʼи спільно використовують багато ресурсів, тож логічно, що вони також спільно використовують простір імен процесів. Однак деякі контейнери можуть очікувати ізоляції від інших, тому важливо розуміти відмінності:

1. **Процес контейнера вже не має PID 1.** Деякі контейнери відмовляються запускатися без PID 1 (наприклад, контейнери, що використовують `systemd`) або виконують команди на кшталт `kill -HUP 1`, щоб надіслати сигнал процесу контейнера. У Podʼах зі спільним простором імен процесів `kill -HUP 1` надішле сигнал пісочниці Podʼа (`/pause` у наведеному вище прикладі).

1. **Процеси видимі іншим контейнерам у Podʼі.** Це стосується всієї інформації, видимої в `/proc`, як-от паролів, переданих як аргументи або змінні середовища. Її захищають лише звичайні права доступу Unix.

1. **Файлові системи контейнерів видимі іншим контейнерам у Podʼі через посилання `/proc/$pid/root`.** Це полегшує налагодження, але також означає, що секрети у файловій системі захищені лише правами доступу файлової системи.
