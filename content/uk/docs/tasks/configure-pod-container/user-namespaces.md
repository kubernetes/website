Ця сторінка показує, як налаштувати простір імен користувача для Podʼів. Це дає змогу ізолювати користувача, від імені якого працює контейнер, від користувача на хості.

Процес, що працює як root у контейнері, може працювати як інший (не root) користувач на хості; іншими словами, процес має повні привілеї для операцій всередині простору імен користувача, але не має привілеїв для операцій за межами простору імен.

Цю можливість можна використовувати, щоб зменшити шкоду, якої скомпрометований контейнер може завдати хосту або іншим Podʼам на тому самому вузлі. Є [кілька вразливостей безпеки][KEP-vulns] з оцінкою **HIGH** або **CRITICAL**, якими неможливо було скористатися, коли простори імен користувача активні. Очікується, що простори імен користувача також помʼякшать деякі майбутні вразливості.

Без простору імен користувача контейнер, що працює як root, у разі втечі з контейнера має привілеї root на вузлі. А якщо контейнеру надано певні можливості (capabilities), вони діють і на хості. Коли використовуються простори імен користувача, усе це не так.

[KEP-vulns]: https://github.com/kubernetes/enhancements/tree/217d790720c5aef09b8bd4d6ca96284a0affe6c2/keps/sig-node/127-user-namespaces#motivation

Якщо у вас різні вузли і лише деякі з них підтримують простори імен користувача для Podʼів, також потрібно забезпечити, щоб Podʼи з просторами імен користувача [призначалися](/docs/concepts/scheduling-eviction/assign-pod-node/) на відповідні вузли.

## Запуск Podʼа, що використовує простір імен користувача {#create-pod}

Простір імен користувача для Podʼа вмикається встановленням поля `hostUsers` у `.spec` у значення `false`. Наприклад:

{{% code_sample file="pods/user-namespaces-stateless.yaml" %}}

1. Створіть Pod у вашому кластері:

   ```shell
   kubectl apply -f https://k8s.io/examples/pods/user-namespaces-stateless.yaml
   ```

1. Підʼєднайтеся до Podʼа через exec і виконайте `readlink /proc/self/ns/user`:

   ```shell
   kubectl exec -ti userns -- bash
   ```

Виконайте цю команду:

```shell
readlink /proc/self/ns/user
```

Вивід подібний до такого:

```shell
user:[4026531837]
```

Також виконайте:

```shell
cat /proc/self/uid_map
```

Вивід подібний до такого:

```shell
0  833617920      65536
```

Потім відкрийте оболонку на хості й виконайте ті самі команди.

Команда `readlink` показує простір імен користувача, у якому працює процес. Він має відрізнятися, коли команду виконують на хості і в контейнері.

Останнє число у файлі `uid_map` у контейнері має бути 65536, а на хості — більшим.

Якщо ви запускаєте kubelet у просторі імен користувача, потрібно порівняти вивід команди в Podʼі з виводом, отриманим на хості:

```shell
readlink /proc/$pid/ns/user
```

замінивши `$pid` на PID kubelet.
